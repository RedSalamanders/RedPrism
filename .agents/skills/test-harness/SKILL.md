# Test harness

Read `Specs/Testing/Testing_Validation.md` for the gates, and the owning domain spec for the expected numbers.

## Suites

| Executable | Scope | Notes |
| --- | --- | --- |
| `HostTests` | Pure functions of the host (`AdapterSelection.h`, `FrameScheduler.h`, `CommandLine.h`, `EditorTool.h`), DirectWrite glyph presence, STRINGTABLE of `RedPrism.exe` | No window, no device; `--asan-probe` is the sanitizer probe |
| `DocumentTests` | `Common/Document.*`, `DocumentHistory`, `TransformEdit`, `Selection` (Clipper2), `BrushStroke` (sparse rasters, the CPU kernel), `Heal`, `ImageFilters`, `WarpStroke` | CPU only |
| `IoTests` | `ProjectStore`, `ImageCodecs` | Needs COM (`CoInitializeEx`), writes under `%TEMP%\RedPrism.IoTests` |
| `CompositionTests` | `CanvasRenderer`, `CanvasViewport`, `GpuBrushCoverage` (the compute brush against the CPU kernel), sparse upload and stroke preview | Creates its own WARP device; reads pixels back |
| `RedPrism.exe --self-test --warp` | Window + swap chain + chrome + composition lifetime | Hidden; exit 0 only when every assertion holds |
| `RedPrism.exe --screenshot` | Harness captures for docs and specs | `Common/WindowCapture.cpp`; never Computer Use |
| `RedPrism.exe --bench brush` | The legacy 4K brush benchmark on the selected device (`--warp` for WARP) | Prints `BRUSH BENCH` lines; record them under `Specs/TestRuns/`, never as a gate |

## Style

- One `Expect(condition, "suite.case")` per observable fact; print `PASS`/`FAIL` lines; return nonzero on failure.
- Goldens are independent numeric expectations (`numeric-goldens` skill), with their tolerance written into
  the owning spec table. On failure print the actual values (`PrintPixels`) so WARP-vs-hardware
  drift is diagnosable from `test.ps1` output.
- Behavior with no legacy counterpart uses the independent reference named by its owning spec. Worker tests
  use serial coordinate formulas and event-gated state transitions; failure timeouts detect deadlock, never
  assert a performance threshold. Keep existing legacy goldens unchanged.
- GPU tests use 2×2 documents with `LayerSampling::Nearest` unless the case is about sampling; `Harness::Render`
  invalidates, composes and reads back BGRA rows.
- Fixture manifests are hand-written JSON checked in under `Tests/IoTests/Fixtures/`; the PNG assets are generated by
  the test (`EncodePngFile`) so binaries are not committed. Remove stale files before writing (`std::filesystem::remove`).
  `MinimalManifest(version, extraLayerFields, extraRootFields)` injects overrides first so yyjson's first-key-wins
  lookup sees them.
- Negative cases assert the exact `ProjectIoStatus` / `ImageCodecStatus` / `DocumentStatus`, not just failure.
- Brush goldens compare the two coverage engines, sparse and dense sampling, and stroke against source-over
  coverage within a named tolerance (2/255) rather than against fixed pixels; "never materialized" is asserted with
  `Raster::IsMaterialized()` after commit, thumbnail, display and the next stroke.
- Never sleep, poll, or rely on wall-clock timing in a test; the screenshot delay lives in the application, not in
  tests.
- The self-test runs on a keyboard of its own (`RedPrism/KeyboardState.h`): input code reads modifiers with
  `KeyboardState::Held` / `Read`, never `GetKeyState` / `GetKeyboardState`, and self-test drivers hold keys with
  `KeyboardState::Write` (`HandleAccelerator` does). Windows writes every physical key transition into each thread's
  key state at once, the hidden self-test window's included, so a direct read lets the user's typing fail a step.
- ASan Debug runs the same executables; parser and tile code must pass there before a phase closes.

## Adding a gate to `test.ps1`

Add the executable after the existing suites, throw on nonzero exit, and keep expected-failure children (probe,
unknown switch) from leaking their exit code into `$LASTEXITCODE`. Record the gate row in `Testing_Validation.md`.
