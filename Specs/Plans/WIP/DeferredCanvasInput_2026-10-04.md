## Required protocol

One admitted stream owns its physical Down, every accepted path sample and one Up/Lost terminal. Stored context
and samples are trivial values in reusable fixed storage. Separate terminal storage guarantees that a full path
ring cannot lose release. Overflow refuses the offered sample, reports quota refusal and ends only the accepted
prefix once through the owning tool's pointer-loss policy. It does not coalesce a painting path or reinterpret a
sample with a later viewport. A consumed terminal remains owned until dependent acknowledgement; stale openings
cannot produce, consume or release a reused stream. A second gesture may be explicitly refused while this one
owns the selected ordinal; that refusal must never become a continuation of the admitted path.

The initial private caller uses 512 path slots plus one terminal. Ordinary Brush/Eraser waits behind opacity inputs
only, captures its document/layer/mask/tool and tip/color/mask palette at physical Down, and captures each later
sample's document coordinates using that sample's current view. The selected host ordinal first acknowledges
opacity closure, then replays at most one stored sample per owner action. Empty live storage blocks on input or
completion events; it creates no timer or polling loop. Other mutations retain their order behind this stream.
Failure before replay preserves the field and document and drops the unpainted stream. Pointer loss preserves
the accepted brush prefix; late moves/up cannot extend it.

The producer admits only this first caller subset. Other tools, preceding non-opacity inputs, Escape/Undo policy,
competing buttons, live gesture co-existence and lifetime/shutdown paths need explicit migration and tests. Brush
pixel execution/finish still uses the existing engine and history path; this input fix does not qualify their
worker placement, UI duration, throughput or G1.

## Validation reference

captured coordinates/modifiers/targets, FIFO order, wrapped and capacity-one storage, full-ring terminal,
overflow accepted-prefix coordinate, exact stale authority, zero/maximum openings, ownership through terminal

`canvas-brush-opacity.*` sends actual OnPointer/WndProc events while the opacity worker is event-gated. It checks

event-time view coordinates remain exact, late loss events add nothing, failed closure paints nothing and keeps
the typed field, overflow preserves only the accepted prefix, and two Undo commands restore the brush then the
original opacity. These tests have been prepared; runtime results remain unchecked until the qualifier finishes.

## Next caller slice after the first runtime gate

Before expanding the qualified caller scope, add independent Eraser and selected-mask scenarios to the same held
opacity-worker driver. Eraser uses an opaque literal source and must clear only the captured small tip/path;
mask painting must retain the physical Down's white/black palette while the later palette changes. A failed
closure must retain both source bytes and the typed opacity field, with zero stroke history entries.

Escape and the first Undo during an admitted but unreplayed stroke cancel that stroke exactly once through a
terminal cancellation state; they must not strand the selected ordinal until a future physical Up. Escape after
partial replay cancels the pending brush transaction and releases its overlay. A late Up belongs to the cancelled
opening and cannot commit work. Redo, target/tool changes, imports, Save and close requests need their declared
ordering or settlement policy and an exact receipt. Preserve opacity closure as a distinct history entry where
its acknowledged change actually landed. These expectations require explicit tests before implementation is
qualified; the first eight pointer cases alone do not cover them.

The private next slice records cancellation against the admitted stream's exact opening, then retires it through
the selected owner action. A replayed stroke also retains its core stroke opening and document serial. Every
subsequent path sample validates that core opening; failed/cancelled retirement cancels only that same core owner.
Three explicit authority fault seams replace the core stroke or document after replay and require old cancellation
or queued path data to leave the new green tip/stroke and history untouched. These seams prove ownership defense;
they do not claim actual replacement-document or second-gesture routing is migrated.
The selected host's document-serial check precedes replay: after document replacement its old receipt must be
Stale, even if an Escape cancellation was recorded. Cancellation within the same document remains Cancelled.
Source review found that the still-frozen first fixture expects Cancelled for both. Preserve that attempt before
correcting its new-fixture receipt expectation; keep the independent new-owner/history/green-tip checks unchanged.

Competing-button cases cover a refused second Down, right Up, lost capture during refusal, a second complete
gesture after an earlier terminal was consumed but its acknowledgement is pending, and a new admitted opening
after retirement. The first stream's coordinates, terminal, transaction and receipt remain bound to its opening.
Right Down/Up is refused without ending the accepted left path. A repeated left Down while sampling is refused
and ends the original accepted prefix as Lost at its last accepted point: later samples of that ambiguous refused
gesture cannot append. A second Down after terminal admission leaves that already closed prefix unchanged.
The refused right Up also preserves the original left path's Windows capture, not only its queue state.
Lifetime cases close/replace the document, cancel a pending save prompt, and end/shutdown the session before and
after replay begins. Every case must release its input budget, worker retirement reservation and captured values
without an owner-thread graph destruction or synchronous opacity fallback.

### Lifetime implementation constraints

The current private first caller keeps the selected host ordinal while a live stream waits for input. A Close,
New, Save or target/tool command queued behind it must therefore have an explicit end/preflight policy; merely
queuing the command can leave it waiting for a physical Up that never arrives. Existing prompt behavior remains
the reference: the close's Cancel response must not itself settle a pending edit, and older independently
admitted work may still acknowledge while the prompt pumps. Do not synthesize Lost merely to reach a Cancel
prompt; do not roll back an older acknowledged opacity closure to simulate that preservation.

Prepare and test the following routes before claiming lifetime migration:

1. Nonmutating discard preflight can ask while an older stroke owns its ordinal. Cancel retires only that close
   request and leaves the captured stream/core owner available to continue. It cannot cancel unrelated host work.
2. Save acceptance closes the captured path once, acknowledges its original opacity/stroke, writes that exact
   revision, then performs the dependent close/replacement. No second prompt or recapture changes the answer.
3. Don't Save acceptance stops physical sampling, retires only this stream's core owner and captured values,
   then permits the already admitted close/replacement. Stale/failed closing input cannot destroy another session.
4. A tool/target command or an explicit standalone Save that ends a stroke seals only its accepted prefix; later
   moves/Up cannot extend it. Admission refusal must not publish the dependent command or reinterpret its input.
5. Shutdown/critical session end closes producer admission first, detaches the same owned stream/CPU/GPU graph
   into the existing acknowledged worker retirement protocol, and joins every producer before destroying sinks.

Each route needs held-before-replay and live-after-replay cases, exact close/cancel/write receipts, original
typed-field/history/pixel expectations, and zero leftover input, worker, GPU row and event reservations.
