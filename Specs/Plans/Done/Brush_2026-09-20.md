## Closeout (2026-09-21)

Shipped as a continuous-tip stroke model (`Common/BrushStroke.*`, the legacy `BrushStroke.swift` and
`MetalBrushCoverage` semantics: centripetal Catmull-Rom subdivision, settled segments plus a replaced provisional
tail, density integration for soft tips, the opacity cap) on a 256² tile grid of the layer's own pixels grown to
the canvas; a `cs_5_0` compute engine on the application device with the settled density kept on the GPU and only
the 0–255 preview read back, and the CPU kernel as the test engine and fallback; sparse `Raster` storage
(base + tiles + fill, `Replacing`, lazy `Data()`) so mouse-up installs a snapshot that shares every untouched tile
and never assembles the layer; and a composition stroke preview (a working texture updated tile by tile, adopted
into the raster cache on commit) with GPU assembly of sparse rasters. The header (mode, size, hardness, opacity,
mask paint or color swatch), the tip cursor, `[` `]` Shift-`[` `]` and digit keys, Shift-click lines, Escape,
`--demo brush` and `--bench brush` are in `Application` / `ChromeHost`.

Deviations from the legacy app, recorded in the owning specs: tiles are composed on the CPU from the read-back
coverage (the legacy app composed on the GPU as well); the eraser is its own tool and the Brush's Erase mode both
map to the same erase stroke; a single digit sets the layer's opacity with the Move tool (the legacy app had no
key there); the brush cursor is a plain ring without the legacy size preview while resizing; the benchmark's frame
time includes a vsync-bound Present, so the update time is the comparable number. Gates: `test.ps1` Debug,
Release and ASan Debug, `build.ps1 -Platform ARM64 -Configuration Debug`, `format.ps1 -Check`,
`validate-skills.ps1`.
